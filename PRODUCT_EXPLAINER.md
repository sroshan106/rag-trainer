# Product Explainer: RAG Engine

A complete guide to the product vision, user workflows, feature capabilities, and design decisions of the local RAG engine.

---

## 1. Product Overview & Core Vision

**RAG Engine** is a self-contained, air-gapped retrieval-augmented generation platform designed to run entirely on local consumer hardware. It enables users to ask questions against private document collections with zero data egress, zero external API costs, and full source attribution.

### Core Value Propositions
1. **Total Data Privacy:** All processing—document parsing, chunk vectorization, database storage, cross-encoder reranking, and LLM text generation—happens on the local host. No proprietary documents or queries ever touch an external cloud or third-party API.
2. **Grounded, Verifiable Answers:** Answers are strictly synthesized from retrieved document chunks. The system deterministically computes document citations and lets users verify claims by inspecting the exact row, line, or page in the source document.
3. **Calibrated for Commodity Hardware:** Engineered from the ground up to operate reliably on entry-level GPUs (baseline: 4GB VRAM) without out-of-memory crashes or silent performance degradation.
4. **Comprehensive Evaluation & Observability:** Built-in benchmark harness with live suite execution, custom test dataset management, side-by-side retrieval comparison ("Impact Check"), and real-time hardware telemetry.

## 2. Product Features & User Workflows

The application interface is organized into five core views plus an integrated Document Viewer:

```
┌────────────────────────────────────────────────────────────────────────┐
│                              RAG Engine                                │
├───────────┬──────────────┬─────────────┬───────────────┬───────────────┤
│    Ask    │    Ingest    │   System    │   Benchmark   │   Settings    │
└───────────┴──────────────┴─────────────┴───────────────┴───────────────┘
```

### 2.1. Ask (Conversational Grounded Q&A)

The primary interface for querying ingested knowledge collections.

- **Explicit Model Selection:** Users select their preferred downloaded LLM (`llama3.2:3b`, `qwen3:4b`, `gemma2:2b`, etc.) from the dropdown. There is deliberately no hidden default fallback—users maintain conscious control over model quality and memory requirements.
- **Real-Time Token Streaming with Stage Indicators:**
  - Watch the pipeline execute in real-time through animated stage pills: **Retrieve** → **Grade** → **Generate**.
  - Text tokens stream incrementally as generated by Ollama.
- **Answer Confidence & Generation Telemetry:**
  - Displays a **Confidence score (0–100%)** representing the relevance of the highest-matching context passage.
  - Displays generation throughput (**tokens/sec**) and detailed timing breakdowns (**rerank latency** and **generation latency**).
- **Interactive Citations:**
  - Shows source cards listing file name and specific unit locator (e.g., `row 42`, `line 105`, `page 3`).
  - Clicking any citation badge opens the integrated **Document Viewer** scrolled directly to the cited unit.
- **Query History Sidebar:**
  - Automatically records past questions, generated answers, citation references, and performance metrics.
  - Supports individual query deletion and one-click history clearing.
- **Honest Refusal Handling:**
  - When the collection is empty or query context is insufficient, the system returns an honest refusal (*"I don't have enough context to answer that question."*) rather than fabricating an answer.

---

### 2.2. Ingest (Knowledge Base Management)

The control center for uploading and indexing documents into the local pgvector database.

- **Broad File Format Support:** Ingest structured and unstructured documents directly:
  - **Spreadsheets & Data:** `.csv` (rendered as interactive tables)
  - **Structured Records:** `.json` (arrays/objects) and `.jsonl` (line-by-line JSON)
  - **Documents & Prose:** `.txt`, `.md` (markdown), and `.pdf` (paginated PDF extraction)
- **Chunking Algorithm Selection:**
  - **Semantic Recursive (`recursive`, default):** Respects sentence and paragraph boundaries using a token-aware encoder (1000 characters with 150-character overlap).
  - **Fixed Token (`token`):** Splits purely on token count for uniform chunk sizes.
- **Live Ingest Progress Bar:**
  - Tracks upload, document parsing, chunk splitting, batch embedding progression, and full-text GIN index construction.
- **Duplicate Detection & Integrity:**
  - Computes SHA-256 file hashes on upload. Duplicate files are rejected immediately (HTTP 409) with a notice indicating when the identical file was previously ingested.
- **Document Management Table:**
  - Lists all ingested files with metadata: filename, timestamp, size, document unit count, and generated vector chunk count.
  - Offers one-click document deletion that atomically cleans up file storage, vector embeddings, and full-text indexes.

---

### 2.3. Document Viewer & Unit Inspector

A dedicated viewer that lets users explore uploaded files exactly as the ingestion pipeline and AI model see them.

- **Accessible via:**
  - Direct citation clicks in the **Ask** view (opens modal).
  - Document rows in the **Ingest** view (opens modal or full-page route `/documents/:fileId`).
- **Stable Addressable Units:**
  - **CSV / JSON:** 1-based row index (spreadsheet numbering).
  - **JSONL / TXT / Markdown:** 1-based line number.
  - **PDF:** 1-based page number.
- **Rich Formats:**
  - Renders CSV files as interactive data tables with custom columns.
  - Renders prose and markdown as formatted text blocks.
- **Jump-to-Unit Locator:**
  - Directly highlights and scrolls to any cited passage so users can audit factual accuracy.

---

### 2.4. Benchmark Suite & Retrieval Comparison

An evaluation workbench designed to measure retrieval accuracy and answer quality quantitatively.

- **Built-in & Custom Benchmark Datasets:**
  - Ships with standard evaluation suites: Single-passage QA, Multi-passage QA, and No-answer refusal sets.
  - **Custom Test Uploads:** Upload your own CSV test questions with question, answer, and target document index columns. Includes metadata validation and dataset deletion.
- **Concurrent Test Execution:**
  - Configure worker concurrency, sample size, chunk size, and result caching.
  - Interleaves test suites in round-robin batches so metrics advance together even on interrupted runs.
- **Quantitative Metrics Dashboard:**
  - **Recall@k:** Percentage of questions where relevant passages were successfully retrieved.
  - **Mean Overlap:** Keyword alignment between expected and actual answers.
  - **Pass Rate:** Proportion of questions answered correctly based on ground truth.
  - **Correct Refusal Rate:** Accuracy on unanswerable questions.
  - **Combined Right:** Overall system composite score.
- **Retrieval Impact Check (A/B Comparison):**
  - Compare the **RAG-Grounded** answer against the **Direct (Raw LLM)** answer side-by-side for any prompt and model.
  - Demonstrates exactly what retrieval, vector search, and reranking added to the model's response.

---

### 2.5. System Telemetry & Health Monitoring

Real-time 1Hz dashboard providing full visibility into host hardware utilization.

- **CPU Utilization:** Overall processor load percentage, per-core utilization bars, and system load averages.
- **System Memory:** Virtual RAM and Swap memory gauges (used vs total MB).
- **Disk Storage & I/O:** Total disk capacity, free space percentage, and live read/write byte throughput.
- **NVIDIA GPU Telemetry:**
  - Live GPU compute utilization percentage.
  - Dedicated VRAM gauge (used MB vs total capacity).
  - Operating GPU temperature (°C) and power draw (Watts).

---

### 2.6. Settings & Model Management

The model registry and download manager for local AI inference.

- **Chat Model Library:**
  - Browse curated models sized for local execution: `llama3.2:3b`, `llama3.2:1b`, `qwen3:4b`, `qwen2.5:3b`, `gemma2:2b`, `phi3.5`.
  - View model parameters, minimum VRAM requirements, disk size, context window length, and strengths.
  - One-click model pull directly from Ollama with real-time download progress and cancel support.
  - Delete unused models to reclaim disk storage.
- **Cross-Encoder Reranker Library:**
  - Manage precision reranker models downloaded from Hugging Face Hub (e.g., `ms-marco-MiniLM-L-6-v2`, `bge-reranker-base`, `mxbai-rerank-base-v1`, `jina-reranker-v2`).
  - View local cache presence and active reranker status.
- **Embedding Model Status:**
  - Displays the active embedding model (`nomic-embed-text`, 768 dimensions, 8192 context).
  - Clear explanations of why embedding models are pinned to maintain vector collection integrity.

## 3. Product Decisions & Design Rationale

| Product Decision | Why It Was Chosen | User Impact |
|---|---|---|
| **No Default Model Fallback** | Silently falling back to an unverified model leads to unexpected RAM spikes or missing model errors. | User explicitly chooses an installed model before asking a question. |
| **Deterministic Refusal Over Guessing** | Hallucinations on off-topic questions destroy user trust in enterprise and research contexts. | System explicitly states when context is missing rather than guessing. |
| **Code-Computed Citations** | Small local models (1B–4B) frequently fabricate or misformat inline citations. | Citations are guaranteed to represent passages actually retrieved and graded. |
| **Integrated Document Viewer** | Users need to verify AI answers against original documents without switching apps. | One-click transition from citation pill to source passage in context. |
| **Interleaved Benchmark Suites** | Traditional sequential suite execution leaves later suites un-scored if a run is cancelled. | Users can run quick partial benchmarks and still get balanced metric estimates. |
| **Side-by-Side Impact Check** | Non-technical stakeholders often ask what vector search actually achieves over raw AI. | Visual side-by-side proves how RAG grounds the model in private data. |
| **Read-Only Embedding Setting** | Changing an embedding model without re-indexing corrupts vector similarity searches. | Prevents silent corpus corruption while educating users on vector dimensions. |
